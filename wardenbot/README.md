# Warden Bot · v1.0.1

Дискорд-бот для русскоязычного сервера Варденов в Foxhole. Он строит сервер по плану (роли, каналы, права), проводит допуск, ведёт доску операций с записью по слотам, пишет напоминания, публикует цели штаба и повышает игроков по правилам.

**Статус:** версия для предстартовой проверки закрытого сообщества на одном Discord-сервере. Проверены миграции SQLite, права, конкурентные действия и восстановление после перезапуска на Python 3.14. Ответы Discord в автотестах моделируются; перед открытием выполните [проверку на сервере](docs/RELEASE_1_0.md).

Текущий этап и оставшиеся ограничения: [план разработки](docs/DEVELOPMENT.md).

## Что умеет v1.0.1

| Модуль | Что делает |
|---|---|
| `/setup run` | Создаёт 9 основных английских ролей и 2 роли уведомлений, сохраняет структуру категорий и каналов. Проверка, правила и служебные сообщения — на русском. Объекты связываются по ID; прежние роли переименовываются без удаления. Каналы после проверки переименовываются на русский; права и содержимое торговли сохраняются. Старые вспомогательные роли сохраняются, новые языковые роли не создаются. |
| Допуск | Кнопка проверки → русская форма (ник, необязательные клан и Steam) → код `WH-XXXX` в игровой чат → один скриншот с F1 и чатом через `/verify screenshot` → русская карточка «Подтвердить / Отклонить». Отказ требует причины. Выдача роли повторяется после ошибок и перезапуска. |
| Операции | Создание, редактирование всех полей с сохранением записей и поставок, открытие/закрытие набора, отмена с причиной и ручное завершение. Брифинг T−45, напоминания T−60/T−15, архивирование перед удалением. |
| Комнаты | Три голосовых канала обычной операции и один у малой группы; удаление при завершении/отмене, восстановление удаления после сбоя. |
| Обращения | Кнопки «Вопрос» и «Жалоба», приватные чаты с модерацией; предложения в отдельном форуме ШТАБА. |
| Меню | `/menu` подтверждает вызов до чтения БД; основные кнопки восстанавливаются после перезапуска. Новичкам доступны проверка и помощь. |
| Снабжение | Обещания участников и отдельное подтверждение доставки. Доставка и боевая явка дают максимум одно участие за операцию. |
| Модерация | Отзыв допуска, повторная проверка при новой войне, мут/снятие мута, бан/разбан с проверкой иерархии. |
| Надёжность | Очереди уведомлений и обновления карточек в БД, сверка потерянных подтверждений Discord, запрет двух процессов на одну БД. |
| Явка и звания | Verified: 0–6, Member: 7–29, Veteran: от 30 подтверждённых завершённых операций. `/operation attendance` явно отмечает присутствие; простая запись не засчитывается. Повторное подтверждение не удваивает счётчик. Исправление явки пересчитывает роль. Три неявки подряд закрывают запись на 7 дней. |
| Цели штаба | `/priority set 1..5` русские посты в канале целей, редактируются на месте. |
| Прочее | `/member admit/rank/info/vouch`, `/timezone set/show`, `/help`, журнал действий в канале штаба, кнопки выбора уведомлений. |

Интерфейс работает на русском независимо от старых ролей `ru`/`engl` и языка клиента.
Названия slash-команд остаются английскими: `/menu`, `/operation create`, `/verify`.
Англоязычное сообщество и автоматический перевод отложены.


## Что понадобится

* Python 3.14 (или Docker).
* Аккаунт Discord, свой тестовый сервер и позже боевой.
* Любой компьютер для проверки, затем сервер, где бот будет работать круглосуточно (см. `docs/HOSTING.md`).

## Шаг 1. Создать приложение и токен

1. Откройте <https://discord.com/developers/applications> → **New Application** → назовите (например, «Warden Bot»).
2. Слева **Bot**. Нажмите **Reset Token** и скопируйте токен. Его видно один раз. Токен это пароль бота: никому не показывайте, в чат и в репозиторий не вставляйте.
3. Там же, в блоке **Privileged Gateway Intents**, включите **Server Members Intent**. `MESSAGE_CONTENT_INTENT=false` можно оставить: архив содержит карточки, переписка не копируется.
4. Слева **Installation** → в **Install Link** выберите **None**, а на странице **Bot** выключите **Public Bot**. Так никто чужой не сможет пригласить вашего бота.
5. Слева **General Information** → скопируйте **Application ID**.

## Шаг 2. Подготовить сервер и пригласить бота

1. Создайте пустой тестовый сервер (потом то же самое повторите на боевом).
2. **Включите режим «Сообщество»**: Настройки сервера → Включить сообщество. Без него нельзя создать форумы. Discord попросит каналы правил и обновлений, выберите любые временные: бот переназначит их сам.
3. Соберите ссылку-приглашение. Права рассчитаны из того, что бот реально делает, **администратора бот не просит**:

   ```
   https://discord.com/oauth2/authorize?client_id=ВАШ_APPLICATION_ID&permissions=1428345187574&scope=bot%20applications.commands
   ```

   Или командой `python -m wardenbot.invite ВАШ_APPLICATION_ID`, она напечатает ту же ссылку.
4. Откройте ссылку, выберите сервер, подтвердите.
5. **Важно:** Настройки сервера → Роли → перетащите роль бота **на самый верх** списка (под вас). Иначе бот не сможет выдавать и упорядочивать свои роли.

## Шаг 3. Запустить бота у себя

Windows (обычная командная строка `cmd`, активировать окружение не нужно):

1. Проверьте, есть ли Python: `py --list`. Нужна версия 3.14. Если пишет «No suitable Python runtime found» или список пуст, установите Python с <https://www.python.org/downloads/windows/> и **поставьте галочку «Add python.exe to PATH»**. Либо: `winget install Python.Python.3.14`. После установки откройте командную строку заново.
2. Дальше по порядку:

```bat
cd /d E:\wardenbot
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
notepad .env
.venv\Scripts\python.exe -m wardenbot
```

`py -3.14 -m venv` явно выбирает Python 3.14. Команды `Activate.ps1` и `activate` не нужны: мы вызываем `python.exe` из `.venv` напрямую. (`Activate.ps1` работает только в PowerShell и при разрешённых скриптах, а в `cmd` он не запускается вовсе.)

Linux / macOS:

```bash
cd wardenbot
python3.14 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env
python -m wardenbot
```

В `.env` впишите минимум:

```
DISCORD_TOKEN=токен_из_шага_1
DEV_GUILD_ID=ID_тестового_сервера
```

ID сервера: в Discord включите «Режим разработчика» (Настройки → Расширенные), правый клик по иконке сервера → «Копировать ID сервера».

Успешный запуск выглядит так:

```
INFO  wardenbot.bot: Synced 7 slash commands (dev guild)
INFO  wardenbot.bot: Logged in as Warden Bot#1234 (…) in 1 guild(s)
```

С `DEV_GUILD_ID` команды появляются мгновенно. Без него это глобальные команды: первый раз они могут появляться до часа.

## Шаг 4. Первая настройка и проверка (на тестовом сервере)

1. В любом канале выполните `/setup run`. Займёт 1–3 минуты. Бот ответит списком созданного. Если что-то не вышло, он скажет, что именно.
2. Проверьте `/setup status`: у всех ролей и каналов должна стоять галочка.
3. Назначьте себе роль **Moderator** (или **Admin**) вручную. Права администратора Discord у вас и так есть, но роли бота выдаёт и проверяет именно по ним.
4. Прогон по сценарию (удобно вторым аккаунтом или с другом):
   * Второй аккаунт нажимает кнопку допуска в канале допуска → заполняет форму → выполняет `/verify screenshot` → вы одобряете в канале очереди → аккаунт получает роль Verified и видит операции.
   * `/operation create` → тип операции → заполнить обе формы → «Опубликовать». В форуме появится пост.
   * Второй аккаунт нажимает «Записаться», выбирает слот. Карточка обновляется через пару секунд.
   * В управлении операцией проверьте «Начать сейчас», снабжение (`BMats +200`). Подтвердите участников через `/operation attendance operation:<ID> player:<участник> attended:True`, затем нажмите «Завершить».
   * `/priority set 1` публикует первую цель в канале целей.
5. Если нужны поздние каналы (снабжение, отчёты, гайды, голосовые): `/setup run include_later:True`.
6. Если вы меняли права вручную и хотите вернуть как в плане: `/setup run fix_permissions:True`. Это перезаписывает права существующих каналов.

На боевом сервере повторите шаги 2.2–4.1, затем уберите `DEV_GUILD_ID` или оставьте пустым.

## Шаг 5. Запуск на постоянной основе

Бот должен работать круглосуточно. Подбор сервера и цены: `docs/HOSTING.md`.

### Вариант А: Docker (проще всего)

```bash
git clone … wardenbot && cd wardenbot      # или скопируйте папку на сервер
cp .env.example .env && nano .env           # токен; DEV_GUILD_ID оставьте пустым
docker compose up -d --build
docker compose logs -f
```

База лежит в томе `wardenbot-data` и переживает пересборки.

### Вариант Б: systemd (Linux без Docker)

Требуется отдельно установленный Python 3.14: штатный Python Ubuntu 24.04 — 3.12.
Не заменяйте системный Python; для простого запуска используйте Docker выше.

```bash
sudo useradd --system --create-home --home-dir /opt/wardenbot wardenbot
sudo cp -r wardenbot tools requirements.txt .env.example /opt/wardenbot/ && cd /opt/wardenbot
sudo -u wardenbot python3.14 -m venv .venv
sudo -u wardenbot .venv/bin/pip install -r requirements.txt
sudo -u wardenbot cp .env.example .env && sudo -u wardenbot nano .env && sudo chmod 600 .env
sudo -u wardenbot mkdir -p data backups
sudo cp deploy/wardenbot*.service deploy/wardenbot-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now wardenbot wardenbot-backup.timer
journalctl -u wardenbot -f
```

### Резервные копии

База хранит заявки, звания, операции и явку. Копия делается, пока бот работает:

```bash
python tools/backup.py data/wardenbot.db backups     # хранит 14 последних
```

В варианте systemd это уже делает `wardenbot-backup.timer` (каждый день в 04:15). Для Docker:
`docker compose exec wardenbot python tools/backup.py /data/wardenbot.db /data/backups`, затем скопируйте папку с сервера к себе. **Копию надо хранить не только на том же сервере.**

### Обновление

```bash
# Docker
git pull && docker compose up -d --build
# systemd
sudo systemctl stop wardenbot && (обновить файлы) && sudo -u wardenbot .venv/bin/pip install -r requirements.txt && sudo systemctl start wardenbot
```

Схема базы обновляется сама (`PRAGMA user_version`). Перед обновлением сделайте копию.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Configuration error: DISCORD_TOKEN is not set` | Нет файла `.env` рядом с местом запуска или токен пуст. |
| `LoginFailure: Improper token` | Токен скопирован с лишним пробелом или устарел: Reset Token и вставьте заново. |
| `PrivilegedIntentsRequired` | Включите Server Members Intent; если в .env MESSAGE_CONTENT_INTENT=true, включите также Message Content Intent (шаг 1.3). |
| Бот не подключается, таймауты | Discord заблокирован в России с октября 2024 года ([3DNews](https://3dnews.ru/1113647/)). Запускайте бота на сервере за пределами РФ; с домашнего компьютера в РФ нужен VPN. Актуальный статус проверьте сами. |
| Команд нет в списке | Нужен перезапуск после правок; без `DEV_GUILD_ID` новые глобальные команды появляются до часа. Проверьте, что при приглашении был scope `applications.commands`. |
| `/setup run`: «Форумы доступны только в режиме Сообщество» | Шаг 2.2. |
| `/setup run`: «Боту не хватает прав» | Приглашайте заново по ссылке из шага 2.3. |
| Роли не упорядочились | Роль бота надо поднять выше (шаг 2.5) и повторить `/setup run`. |
| Правило AutoMod не создано | Создайте вручную: Настройки сервера → Автомодерация → Создать правило → Ключевые слова → Регулярное выражение `\b\d{6}\b`, действие «Блокировать сообщение», исключения: каналы штаба, допуска и роли Штаб и Командование. |
| Кнопки под старыми карточками «не отвечают» | Бот был выключен. После запуска кнопки оживают сами, повторно ничего публиковать не нужно. |
| Бот отвечает «Что-то пошло не так» | Подробности в логах (`docker compose logs` или `journalctl -u wardenbot`) и в канале «бот» (только Командование). |

## Безопасность и данные

* Бот хранит ссылку на Steam, игровой ник, полк, Discord ID, звания и явку. Скриншоты допуска **не хранятся в базе**, а лишь временно лежат в закрытом канале очереди и удаляются из карточки после решения. Напишите об этом в правилах (в тексте правил это уже есть).
* Токен хранится только в `.env` (`chmod 600`) и не должен попадать в Git. Файл `.gitignore` это учитывает. Если токен утёк: Developer Portal → Reset Token.
* У бота нет прав администратора. Роль «Командование» тоже не администратор Discord: она получает только модераторские права и право банить.
* Защита от вторых аккаунтов в v0.1 держится на допуске: скриншот с кодом, флаги риска и ручное решение модератора. Steam необязателен; совпадение ссылки — предупреждение, а не гарантия уникальности. Бот не умеет проверять фракцию в игре автоматически (такого API нет).

## Обновление существующей установки

Сделайте резервную копию БД, обновите зависимости (`pip install -r requirements.txt`) и перезапустите бота.
Нужен discord.py 2.7+. Миграции схемы применяются автоматически.
На тестовом сервере выполните `/setup run`: роли будут переименованы по сохранённым ID, входные и служебные
каналы приведены к новым языкам и ограничениям. Поднимите роль бота выше управляемых ролей.
Очередь ролей проверяется каждые 30 секунд; нехватка прав не удаляет задание.

**Историческая явка:** прежнее завершение автоматически засчитывало всех записанных. Такие записи сохраняются,
но не считаются подтверждёнными. Организатор/модератор может подтвердить их командой `/operation attendance`
для завершённой операции. Новые пороги применяются к подтверждённой истории; роль может измениться вниз.

## Обновление: русский интерфейс, администратор и архив

1. Остановите бота и сделайте резервную копию SQLite (см. выше).
2. Выполните `git pull` из корня репозитория. Запускайте приложение из вложенной папки `wardenbot`, где лежат `.env` и `requirements.txt`.
3. Перезапустите бота. Команды автоматически синхронизируются без русских названий; глобальные изменения Discord могут отобразиться с задержкой.
4. `MESSAGE_CONTENT_INTENT=false` достаточно: файл обсуждения больше не создаётся.
5. Выполните `/setup run`. Появится канал **архив-операций**, правила и проверка обновятся на русском.
   Бот удалит только свою сохранённую панель из `start`; прочие сообщения не затрагиваются.
6. Проверьте `/menu` → «Создать операцию». Нативный администратор Discord и настроенная роль `Admin`
   могут создавать операции без проверки и привязки к клану. Модераторы также могут организовывать общие операции.

### Архив операций

Завершённые и отменённые операции обрабатываются раз в минуту, включая старые записи.
Бот сохраняет публичную карточку, состав и ресурсы в SQLite, отправляет карточку в архив,
затем удаляет исходный пост с доски. Переписка не читается, файлы обсуждения не создаются.
Закрытый брифинг и комнаты операции в публичный архив не попадают.

Архив фиксирует состояние на момент переноса; последующие исправления явки остаются в основной БД.
Если отсутствует канал, не хватает прав или произошёл сетевой сбой, исходный пост не удаляется.
Очередь переживает перезапуск; перед повторной отправкой бот ищет свою архивную запись по метке.
Голосовые комнаты удаляются независимо от отправки итоговой карточки.
Запускайте только один экземпляр бота на одну БД.

### Кланы

Обычным организаторам по-прежнему нужна привязка к клану:

1. Модератор: `/clan register name:Название` — получает номер клана.
2. Модератор: `/clan assign clan:НОМЕР player:@Игрок duty:leader` — назначает проверенного главу.
3. Глава: та же команда с `duty:delegate` — назначает проверенных делегатов своего клана.
4. Глава или делегат создаёт операцию через `/menu` либо `/operation create`.
5. Автор, глава этого клана и модераторы управляют операцией. Другие делегаты — только своими.
6. `/clan remove player:@Игрок` сразу отзывает полномочия в БД; роль синхронизируется отдельно.

Старые операции без клана доступны своему проверенному автору и модераторам.
Редактирование операций, напоминания 60/15, брифинг T−45, ручное завершение и обещания поставок реализованы в v0.2.0. Обновление существующей установки: [RELEASE_0_2.md](docs/RELEASE_0_2.md).


## Тикеты, небольшие группы и каналы операций

После обновления и перезапуска выполните `/setup run`. Команда переименует сохранённые
каналы на русский (кроме входных, доступных до проверки), добавит «вопросы-и-жалобы»
и панель в «ищу-группу». Форум «предложения» создаётся или переносится в «ШТАБ» с сохранением тем. ID каналов, сообщения и торговые права сохраняются.
Потребуется право бота **Move Members / Перемещать участников**, чтобы отзывать доступ
у уже подключённых игроков; новую ссылку можно получить через `python -m wardenbot.invite APPLICATION_ID`.

- **Тикет:** «Вопрос» или «Жалоба» → название и описание → приватный текстовый канал с модерацией.
  Автор или модератор закрывает обращение. У автора может быть один открытый тикет.
- **Поиск группы:** кнопка → название, задача, общее число людей (включая автора).
  Карточка появляется в том же канале, группа сразу активна. Кнопки позволяют записаться,
  выйти, изменить группу и завершить её. Войс «Название Сбор» указан в карточке.
  Допустимы 1–20 человек и до двух активных групп одного автора. После завершения удаляются войс
  и объявление о поиске группы. При сбое удаление повторяется, в том числе после перезапуска.
- **Обычная/клановая операция:** автоматически создаются «Название подготовка»,
  «Название Войс 1» и «Название Войс 2» в категории «Каналы операций». Все три — голосовые; при завершении/отмене удаляются.
  Доступ получают автор, записавшиеся участники и модерация.
- **Время:** вводите `завтра 20:30`, `сегодня 21:00`, `через 30 минут` или `25.11 19:00`.
  Пояс указан в заголовке формы; изменить его можно через `/timezone set`.
  Предпросмотр показывает выбранное время до публикации.
