# Карта войны Foxhole

В канале «сводка» бот поддерживает одну закреплённую карточку: карта текущей
войны, её номер, фаза и время последней проверки в МСК. Карточка обновляется
на месте каждые 5 минут, без новых сообщений и упоминаний. Регион можно выбрать
в списке под картой: увеличенное изображение увидит только нажавший участник.
Для этого нужен допуск и доступ к сводке либо права модерации.

## Включение

1. Обновите код. На BotHost выполните пересборку с Dockerfile репозитория,
   чтобы установились новые зависимости (Pillow). При обычном запуске:
   `python -m pip install -r requirements.txt`.
2. Оставьте или добавьте переменные:

   ```dotenv
   WAR_MAP_ENABLED=true
   WAR_MAP_SHARD=able
   ```

   Другие официальные игровые серверы: `baker`, `charlie`. Ключ API не нужен.
   Неактивный игровой сервер может не отдавать карту.
3. Перезапустите бота. Если структура сервера уже настроена через бота,
   карта появится в существующем канале сводки в первом цикле обновления.
   Для нового Discord-сервера выполните `/setup run`.
4. Администратор может вызвать `/warmap publish`, чтобы сразу опубликовать
   или восстановить карточку, и `/warmap status` для диагностики. Публикация
   использует последний снимок; загрузка API выполняется фоновым циклом.

Нужны стандартные права бота в сводке: просмотр, история, отправка сообщений,
встраивание ссылок, вложения и закрепление сообщений. Ошибка закрепления
не мешает обновлению самой карточки. Новые slash-команды регистрируются
существующим механизмом бота при запуске.

У уже установленного бота включите право **«Закреплять сообщения»** в роли бота
и убедитесь, что в сводке нет запрета этого права. Либо обновите его разрешения
по ссылке из `python -m wardenbot.invite ВАШ_APPLICATION_ID`, затем выполните
`/setup run`, чтобы обновились права канала. Новое право требуется Discord
отдельно от «Управлять сообщениями».

На BotHost храните SQLite в `/app/data`. Снимок карты, HTTP-кэш и ID карточки
хранятся в той же БД, что и остальные данные. Остановка карты:
`WAR_MAP_ENABLED=false` и перезапуск; существующая карточка останется с прежней
датой, новые просмотры регионов будут отключены. Её можно удалить вручную.

## Что изображено

- Внутри каждого гекса территория каждой базы закрашена цветом её владельца:
  синий — Вардены, зелёный — Колонисты, серый — нейтральные.
- Границы внутренних территорий рассчитаны по ближайшей городской или реликтовой
  базе и ограничены гексом. Публичный API не публикует точные границы игровых
  территорий, поэтому эти линии приблизительные. При отсутствии баз заливки нет.
- Синие метки — Вардены, зелёные — Колонисты, белые — нейтральные.
- Квадраты — базы, ромбы — победные города, кресты — выжженные объекты.
- На общей карте показаны базы и победные города. В увеличении добавлены
  остальные объекты публичного динамического API и названия крупных локаций.
- Это контроль объектов, а не точная линия фронта. API не раскрывает позиции
  игроков, техники и закрытые сведения фракций. Данные могут запаздывать.

Фон из Update 66 включён в репозиторий, охватывает 53 региона и не скачивается
при каждом запуске. Если API добавит неизвестный регион, он появится в списке
как схема координат без фона; общая карточка предупредит об этом.
Обновления географии требуют обновления фонового изображения и таблицы регионов.
[Источники и авторство](../wardenbot/assets/war_map/SOURCES.md).

## Сбои и восстановление

При сетевой ошибке, HTTP 403/429/5xx или неполном ответе остаётся последний
полный снимок с предупреждением о задержке. Если успешного снимка ещё нет,
карточка сообщает, что данные пока недоступны. Следующая попытка автоматическая.
Учитываются ETag, Cache-Control и Retry-After; одновременно выполняется не
более трёх HTTP-запросов. Смена войны обновляет статические данные регионов.

При удалении карточки бот создаёт её заново. Если отправка прошла, но сохранить
ID не удалось, бот ищет своё сообщение по служебной метке перед новой отправкой.
Выбор регионов восстанавливается из SQLite после перезапуска.

`/warmap status` показывает последний успех и ошибку. При HTTP 403 проверьте
доступ с хостинга к `https://war-service-live.foxholeservices.com/api/worldconquest/war`.
Ключи, токен Discord и дополнительные privileged intents для API не требуются.
Для Baker/Charlie используются соответственно `war-service-live-2` и `-3`.

## Проверка после установки

Откройте сводку, выберите регион, дождитесь обновления той же карточки.
Перезапустите бота: ID сообщения должен сохраниться, меню — работать.
Удалите карточку на тестовом сервере: `/warmap publish` должен восстановить её.
Проверьте, что участник без допуска не видит сводку.

Автотесты используют смоделированные ответы API и Discord, а изображения
строятся настоящим Pillow. На этапе разработки официальный API возвращал
HTTP 403 из облачной среды; соединение с живым API и публикация на сервере
требуют проверки после установки на хостинг.

Код разделён на `war_map.py` (API и SQLite), `war_map_render.py` (PNG)
и `cogs/war_map.py` (Discord), чтобы данные и отрисовку позднее использовать на сайте.
