# Wardenbot 1.0 — 23.11.2026

Релиз для одного русскоязычного сообщества с 5–7 кланами, небольшими группами и соло-игроками.
Python 3.14, discord.py, SQLite. EN, сайт, лист ожидания и дополнительные статусы тикетов не добавлены.

## Поведение

- Проверка игрока, клановые полномочия, модерация, запись и снабжение сохраняют свои правила доступа.
- У обычной/клановой операции три **голосовых** канала: подготовка, Войс 1, Войс 2.
  При завершении или отмене удаляются все три. Каналы и их сообщения не архивируются.
- У небольшой группы один войс «Сбор». Завершение удаляет его; карточка остаётся в «ищу-группу»
  с пометкой о завершении, без активных кнопок и ссылки на удалённый канал.
- Архив операций содержит публичную итоговую карточку без файла JSON.gz. Переписка не читается
  и не копируется. Старые уже опубликованные архивные файлы не удаляются задним числом.
- В «вопросы-и-жалобы» две кнопки: **Вопрос** и **Жалоба**. Обращения приватны: автор и модерация.
  Тип сохраняется после перезапуска. Один автор может иметь одно открытое обращение любого типа.
  Закрытый тикет остаётся доступен автору для чтения и модерации для работы.
- **предложения** — отдельный форум в **ШТАБЕ**, доступный проверенным участникам.
  Существующий форум переносится с сохранением его ID и тем.

## Обновление существующей установки

1. Остановите единственный процесс бота. Сохраните копию SQLite:
   `python tools/backup.py data/wardenbot.db backups` из каталога приложения.
2. Выполните `git pull` из корня репозитория. Перейдите в вложенный `wardenbot`, где находятся
   `.env`, `requirements.txt` и пакет приложения. Используйте существующее окружение Python 3.14.
3. Запустите `python -m pip install -r requirements.txt`, затем `python -m wardenbot`.
   На Windows вместо `python` можно использовать `.\.venv314\Scripts\python.exe`.
4. Миграция v8→v9 применяется автоматически. Старые тикеты остаются открытыми/закрытыми как прежде,
   по умолчанию получают тип «Вопрос»; ID каналов, записей и сообщений сохраняются.
5. Выполните `/setup run`: обновятся кнопки тикетов и форум предложений переместится в ШТАБ.
   Повторный запуск восстанавливает прежние объекты и панели по ID/метке.
6. Фоновый цикл заменит существующие текстовые каналы подготовки активных операций на голосовые.
   **Старый текстовый канал подготовки удаляется вместе с перепиской, без архива**, как и комнаты
   уже завершённых операций. Закрытые обращения модерации этим удалением не затрагиваются.

Для нового запуска следуйте [README](../README.md). Нужны режим сервера «Сообщество»,
Server Members Intent, роль бота выше управляемых ролей и права из приглашения
`python -m wardenbot.invite APPLICATION_ID`. `Message Content Intent` для архива не требуется.
Если `/menu` отсутствует, доступно восстановление `python -m wardenbot --sync-commands`.

## Проверка перед открытием

Используйте тестового игрока, организатора и модератора; права обычного игрока нельзя проверить
только учётной записью с Administrator.

1. Новичок видит входные каналы. Проверка → скриншот → решение модератора → роль Verified.
   Другой новичок не видит доску, предложения и приватные комнаты.
2. Создайте клан и назначьте главу/делегата. Создайте операцию на `через 20 минут`, с двумя местами.
   Проверьте предпросмотр времени, три **голосовых** канала и доступ автора/модерации.
3. Запишите второго игрока, проверьте доступ и закрытый брифинг; третья запись не превышает места.
   Выход снимает доступ, включая отключение уже сидящего в войсе игрока.
4. Перезапустите бота: карточка, состав и кнопки работают, комнаты не дублируются. Напоминание
   за 15 минут отправляется один раз; для проверки часового напоминания создайте отдельную операцию.
5. Начните операцию, подтвердите явку/доставку, завершите. Комнаты удаляются, в архиве появляется
   итоговая карточка **без вложений**, пост с доски удаляется после подтверждённой отправки архива.
   Повторный запуск не создаёт удалённые комнаты заново.
6. Создайте небольшую группу на двоих, присоединитесь вторым игроком и завершите её.
   Войс удаляется, карточка становится закрытой. Состав не увеличивается от повторного нажатия.
7. Откройте по очереди вопрос и жалобу: две короткие формы, приватный чат, закрытие автором/модерацией.
   Другой игрок не видит обращения. Опубликуйте предложение в форуме ШТАБА.
8. Временно запретите боту удалять **тестовую** комнату, завершите операцию. Исправьте права:
   удаление должно повториться, остальные доступные комнаты удалятся даже при частичном сбое.
9. Сделайте бэкап, откройте копию SQLite и выполните `PRAGMA quick_check;`: результат `ok`.
   Для проверки восстановления запускайте копию с отдельным тестовым токеном, не второй боевой процесс.

## Надёжность и ограничения

- Данные и промежуточные состояния сохраняются в SQLite. Терминальный статус операции/группы
  является заданием на удаление комнат; при сбое оно повторяется после перезапуска.
  HTTP 404 при повторном удалении считается успехом. При HTTP 403 конкретное задание ждёт
  пять минут или изменения общих прав бота; другие задания продолжаются.
- Уведомления 60/15, архив и панели сверяются с сообщениями бота по меткам. Абсолютной общей
  транзакции между SQLite и Discord нет, поэтому используются повторные попытки и сверка подтверждений.
- Максимум **95 мест** в обычной операции: вместе с автором, ботом и служебными ролями это
  укладывается в лимит 100 разрешений Discord. Изменение старых чрезмерно больших операций
  потребует уменьшить план мест; новые записи сверх 95 не принимаются. Малая группа — до 20 человек.
- В категории Discord максимум 50 каналов: одновременно помещаются до 16 полных операций
  с тремя комнатами. Завершайте операции, чтобы комнаты освобождались. Закрытые тикеты хранятся
  отдельно; сроки удаления их истории определяет модерация.
- Один процесс и **один рабочий Discord-сервер на отдельные токен и БД**. Глобальные slash-команды
  могут отображаться на нескольких серверах, но профили допуска в одной БД общие. Для независимого
  тестового сервера используйте отдельную установку; полной многосерверной изоляции в этом релизе нет.
- Бэкапы публикуются только после успешного копирования и `quick_check`; два запуска в одну секунду
  не перезаписывают друг друга. Ошибка копирования не удаляет предыдущие исправные копии.

При подготовке релиза прошли 188 тестов на Python 3.14. Автоматические проверки используют реальные SQLite/discord.py и подмену сетевого транспорта.
Они проверяют правила и восстановление при сбоях, но не подтверждают реальные разрешения вашего
сервера или доступность Discord из вашей сети. Описанную проверку в живом Discord нужно пройти
после обновления до приглашения аудитории. Команда тестов: `python -m pytest -q`.
