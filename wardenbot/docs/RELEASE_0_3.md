# v0.3.0 — группы, тикеты и каналы операций

## Обновление

1. Остановить единственный процесс бота, сохранить копию SQLite и обновить исходники.
2. Из каталога `wardenbot` обновить зависимости и запустить на Python 3.14:
   `python -m pip install -r requirements.txt`, затем `python -m wardenbot`.
   Схема v7→v8 применяется автоматически; данные старых функций сохраняются.
3. Проверить право бота **Move Members** (добавлено к прежним правам управления каналами).
   При необходимости обновить права через ссылку `python -m wardenbot.invite APPLICATION_ID`.
4. Администратору выполнить `/setup run`. Известные боту каналы переименовываются по ID,
   включая ранее созданные дополнительные каналы. Входные каналы остаются на английском.
   Торговые разрешения и сообщения сохраняются. Панели добавляются в «помощь-и-отзывы»
   и существующий «ищу-группу». Повторно обновить панели: `/setup panels`.

Произвольные каналы, созданные вручную и не зарегистрированные в настройках бота,
автоматически не переименовываются.

## Проверка на тестовом Discord-сервере

Нужны проверенный автор, второй проверенный игрок, новичок и модератор.

1. Новичок не видит групп, тикетов и каналов операций. Завершить обычную проверку игрока.
2. В «помощь-и-отзывы» нажать кнопку, заполнить название и вопрос. В категории обращений
   появится текстовый канал. Автор и модератор могут общаться, другой игрок не видит канал.
   Закрыть тикет: автор читает историю, модератор сохраняет возможность писать.
3. В «ищу-группу» создать «Два танка» на 2 человека. В форме только название, задача и
   размер группы. Карточка появляется здесь же со статусом «Идёт сейчас», автором в составе
   и ссылкой на отдельный войс «Два танка Сбор · ID».
4. Второй игрок присоединяется и получает доступ к войсу; третьему места уже нет.
   Повторное нажатие не добавляет вторую запись. Выход освобождает место и отзывает доступ,
   включая отключение игрока, уже находящегося в войсе.
5. Автор изменяет название/задачу/размер кнопкой «Изменить». Чужое редактирование запрещено,
   число мест нельзя уменьшить ниже текущего состава. Автор завершает группу.
6. Глава клана создаёт обычную операцию: начало `через 30 минут`, длительность `2`.
   Проверить часовой пояс в заголовке и время в предпросмотре. После публикации появляются
   подготовка и два войса. Второй игрок получает доступ после записи и теряет после выхода.
7. Перезапустить бота с открытой группой и тикетом. Старые кнопки работают; карточки,
   каналы и состав восстанавливаются без дублирования. Права перепроверяются по актуальной БД.

## Хранение и восстановление

Тикет — приватный канал Discord с перепиской; бот не копирует переписку в общие каналы.
Закрытые тикеты и подготовительные чаты сохраняются. После закрытия тикета автор может
только читать, после завершения операции доступ к подготовке остаётся у автора и модерации.
Закрытый план не переносится в публичный архив операции. Голосовые каналы после завершения
закрываются для участников. Модерация сохраняет доступ.

Закрытые каналы не удаляются автоматически: их историю и сроки хранения определяет модерация.
Ненужные закрытые каналы можно удалить вручную; бот не создаст их заново. У Discord есть лимит
50 каналов в категории и 100 персональных/ролевых разрешений на канал: освобождайте закрытые
каналы перед достижением лимита. Новые комнаты создаются с доступом только автора/участников
и модерации, без публичного промежуточного состояния.

ID комнат, сообщений и отправленной формы хранятся в SQLite. После сбоя бот ищет комнату
по служебной метке/названию, сообщение — по метке карточки, затем сохраняет подтверждение.
Повторные действия сериализуются; повторная отправка одной формы не создаёт новый объект.
Незавершённые действия повторяются каждые 30 секунд. Доступ к комнатам синхронизируется
после действий с карточкой и фоновым циклом; при массовом отзыве допуска — в ближайшем цикле.
При сбоях Discord возможна дополнительная задержка, причина пишется в журнал бота.
Нельзя запускать несколько процессов бота на одну БД.

При отзыве проверки место игрока в небольшой группе освобождается. Если доступ потерял
автор, группа закрывается. Модераторы/администраторы могут организовывать группы без
обычной проверки. Вновь открыть завершённую группу нельзя — создайте новую.

Автотесты используют SQLite и имитацию Discord API. Они не заменяют проверку прав и кнопок
в реальном Discord после обновления. Запуск: `python -m pytest -q` из каталога `wardenbot`.

## v0.3.1: ошибка 403 при создании категории

В приглашении v0.3 не были явно запрошены `connect` и `speak`, хотя бот разрешал
их в создаваемых каналах. Discord не разрешает боту выдавать отсутствующие у него права.
В v0.3.1 список приглашения исправлен, проверка перед созданием перечисляет недостающие
права. `move_members` больше не выдаётся боту через разрешения категории: оно проверяется
перед отключением игрока от войса. Завершённые старые операции без комнат не создают категории.

После обновления исходников обновите разрешения приложения на нужном сервере:
`python -m wardenbot.invite APPLICATION_ID`. Откройте полученную ссылку и подтвердите права
существующего бота, затем выполните `/setup run`. Удалять бота, базу или каналы не нужно.
В частности, нужны «Управлять каналами», «Управлять ролями», «Подключаться», «Говорить»
и «Перемещать участников». Личные права администратора не передаются боту.

После 403 повтор конкретного задания откладывается на пять минут; остальные задания продолжаются.
Изменение общих прав роли бота запускает повтор уже на следующем 30-секундном цикле.
При исправлении только разрешений отдельного канала повтор будет после задержки.

Предупреждения об отсутствии PyNaCl/davey относятся к передаче звука самим ботом.
Для создания каналов и управления доступом эти библиотеки не требуются.
Строка `Logged in as ...` означает, что запуск и подключение завершились успешно.
Если новый запуск остаётся на `logging in using static token`, это другой этап:
нужны последние строки именно этого запуска для отдельной диагностики подключения.

## v0.3.2: бот онлайн, но slash-команды не появляются

`Logged in ... in 2 guild(s)` означает присутствие бота на двух Discord-серверах,
а не регистрацию команд в двух кланах. При запуске теперь выводятся названия и ID серверов.

`DEV_GUILD_ID` ограничивает регистрацию одним тестовым сервером. Для команд на обоих серверах
оставьте `DEV_GUILD_ID=` пустым в `.env` (переменные окружения процесса имеют приоритет).
После остановки текущего процесса и обновления исходников запустите из каталога приложения:

```powershell
.\.venv314\Scripts\python.exe -m wardenbot --sync-commands
```

На Ubuntu соответствующая команда: `.venv/bin/python -m wardenbot --sync-commands`.
Это обычный запуск бота с принудительной регистрацией; второй процесс параллельно не запускайте.
Ожидаемая строка: `Synced ... slash commands (global (all servers))`.
Изменения глобальных команд могут отобразиться в Discord с задержкой. После синхронизации
обновите клиент Discord и проверьте `/menu`. `/setup sync` остаётся доступна для восстановления
из Discord, когда сама команда видна.

Теперь при совпадении локального кэша бот всё равно читает список команд из Discord. Если
состав команд отличается, регистрация восстанавливается. При исправном списке повторная
запись не выполняется. Старая регистрация тестового сервера удаляется только после успешной
регистрации в новой области; ошибка нового сервера не уничтожает предыдущие команды.

Если команды зарегистрированы, но не видны, проверьте:

- сервер → Настройки → Интеграции → приложение бота → разрешения команд для роли/канала;
- право участника «Использовать команды приложений» в выбранном текстовом канале;
- установку приложения через ссылку `python -m wardenbot.invite APPLICATION_ID`, содержащую
  оба scope: `bot` и `applications.commands`.

Если после этого `/menu` отсутствует, для дальнейшей диагностики нужны строки `Checking`,
`Synced`/`Verified`, `Discord server` и ошибки последнего запуска; токен и `.env` присылать не нужно.
